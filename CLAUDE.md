# diffpilot

Rust app built with GPUI. The Cargo workspace has three app crates: `core` (logic), `ui-kit` (theme, icons, shared components), and `gpui-app` (the app: shell, sidebar, comparison, the diff pane in `src/diff_pane/`, and the review UI in `src/review/`). `xtask` holds the dev tooling, run as `cargo xtask`.

- Run `git config core.hooksPath .githooks` once per clone. The pre-commit hook runs `cargo xtask precommit`: it formats all Rust code and blocks `env!("CARGO_BIN_EXE_…")`, which bakes in another worktree's path.
- When a change adds, changes, removes, or fixes something users can see, add a line under `## [Unreleased]` in `CHANGELOG.md`, in the same commit. Use the `### Added`, `### Changed`, `### Removed`, or `### Fixed` heading. Write it for users, one change per line, 225 characters max. Refactors, tests, and dev tooling need no line.
- Each worktree has its own Cargo build dir under `~/.cargo/build/diffpilot-<hash>/` (set in `.cargo/config.toml`). The first build in a new worktree compiles the dependencies, which takes about 6 minutes. Do not set your own `CARGO_TARGET_DIR`.
- Before you report a code change as complete, run `cargo xtask related` and the commands it prints (`cargo xtask unit <feature...>`, `cargo xtask clippy <crate...>`, `cargo xtask flows`). `unit` picks tests by feature, not by crate. A feature or crate that already passed with the same inputs is skipped.
- Run only the tests that `related` prints. Do not run `cargo xtask unit --all`, `cargo test`, or `cargo test --workspace` unless the user asks. If you think `related` missed a feature, fix the feature table in `xtask/src/features.rs`, do not run everything.
- `cargo xtask perf` and `cargo xtask visual` open windows. Run them yourself when `related` prints them, once per change. Do not re-run benches to chase noise.
- Flow tests in `gpui-app/tests/flows/` act like a user. They click, type, and press keys through the `diffpilot::testing` helpers, and they assert on what the window shows. They do not call view methods or emit events directly. If a helper is missing, add one to `testing.rs` that uses real input.
- Before you open or update a PR, run `cargo xtask baseline` and commit `baselines/bench.json`. After you open it, run `cargo xtask pr-screenshots`; it commits `screenshots/<feature>/` and lists the images that changed. The merged PR then holds the baseline for the next PR. See `.claude/skills/feature-tests`.
